#### Project 1 — AI Smart Travel Assistant

- Problem: Travel planning often requires checking multiple transportation and information sources.
- Solution: An AI-powered travel assistant that combines route planning, transportation options and contextual information.
- Technologies: React, Tailwind CSS, Node.js, Express.js, Python Flask, MongoDB Atlas, Maps API, Weather API.
- Proof to show:
  - Home screen
  - Travel planning interface
  - Route results
  - Architecture
  - ML/service output
  - GitHub repository

#### Project 2 — AI CareerOS

- Problem: Students need multiple disconnected tools for placement preparation.
- Solution: A multi-agent career intelligence platform that brings career guidance, preparation and recommendation capabilities together.
- Technologies: React, Tailwind CSS, Node.js, Express.js, MongoDB, Gemini API, Python recommendation engine.
- Proof to show:
  - Dashboard
  - Career recommendations
  - AI interaction
  - System architecture
  - Recommendation output
  - GitHub repository

#### Project 3 — Urban Heat Risk Intelligence System

- Problem: Urban areas can experience different levels of heat risk depending on environmental and built-up characteristics.
- Solution: An ML-based system for identifying and visualizing areas with higher heat risk using environmental and urban features.
- Technologies: Python, Machine Learning, Pandas, geospatial data and visualization tools.
- Proof to show:
  - Dataset
  - Feature analysis
  - Model results
  - Risk visualization
  - Architecture/workflow

#### Project 4 — CareerPilot AI

- Problem: Students often struggle to identify suitable career paths and prepare for them efficiently.
- Solution: An AI career coach that provides personalized career guidance and recommendations.
- Technologies: React, Tailwind CSS, Node.js, Express.js, MongoDB, Gemini API and Python.
- Proof to show:
  - User interface
  - AI interaction
  - Recommendation output

  - GitHub/demo

## 4. Image Curation

### Image Selection Principle

Real evidence is preferred over generated visuals whenever the image represents actual work.

For project sections, screenshots of the real applications, dashboards, notebooks, GitHub repositories, model outputs and visualizations will be used.

AI-generated images will only be considered for supporting visual elements such as abstract backgrounds or decorative sections.

---

### Selected Image Types

The portfolio should prioritize:

- Real project UI screenshots
- Real dashboard screenshots
- Real ML/model output
- Real charts and visualizations
- Real architecture diagrams
- Real GitHub/project screenshots
- Real internship/project evidence

These images directly support the claims made in the portfolio.

---

### AI Image Selection Criteria

If an AI-generated image is used, it must satisfy all of the following:

1. Supports the section's purpose.
2. Matches the portfolio's visual identity.
3. Does not look like a generic stock image.
4. Does not compete with actual project evidence.
5. Uses a consistent visual language with other supporting images.
6. Adds information or atmosphere without pretending to represent real project output.

---

### Rejected AI Image

**Rejected:** Generic AI-generated technology/coding hero image.

**Reason for rejection:**  
The image communicates a broad idea of technology but does not provide evidence of my actual work. It also risks making the portfolio look generic and takes attention away from real project screenshots.

**Decision:**  
Use a clean hero section with the one-line claim and actual project evidence instead of relying on a decorative AI-generated hero image.

## 6. Design Decision Summary

The portfolio intentionally follows a simple rule:

> Design should frame the work, not compete with it.

The visual system therefore uses:
- One primary font
- A limited four-color palette
- Minimal branding
- Consistent spacing
- Simple cards
- Clear hierarchy
- Real screenshots as primary evidence
- AI-generated visuals only when they add supporting value

The strongest visual elements of the portfolio should be the actual projects, results and evidence.
